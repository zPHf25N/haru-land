# HARU LAND (하루랜드)

> 나의 하루를 기록하면, 나만의 마을이 자랍니다.

공부·운동·휴식·사교 등 현실의 일상 활동을 기록하면 도서관·체육관·공원·카페가 생성되고 성장하는 웹 게임입니다. 기록의 결과를 마을의 변화로 보여 주어 꾸준한 기록과 균형 잡힌 일상을 돕는 개인 학술제 프로젝트입니다.

## 현재 상태

Supabase 백엔드 초기 버전을 구현했습니다. 로그인한 사용자는 일기를 저장하고, 키워드 기반 모의 분석과 사용자 수정을 통해 마을을 성장시킬 수 있습니다. 웹 화면, 실제 AI 모델 연동과 서비스 배포는 개발 예정입니다.

## 핵심 기능

| 일상 활동 | 연결 건물 | 동작 |
| --- | --- | --- |
| 공부 | 도서관 | 활동 기록일을 누적해 해금 및 성장 |
| 운동 | 체육관 | 활동 기록일을 누적해 해금 및 성장 |
| 휴식 | 공원 | 활동 기록일을 누적해 해금 및 성장 |
| 사교 | 카페 | 활동 기록일을 누적해 해금 및 성장 |

- 자유 형식 일기 작성·날짜별 조회·수정·삭제
- 모의 분석으로 활동 태그 추출 및 사용자 수정
- 기록일 기반 마을 XP, 건물 및 확장 구역 상태 저장
- 건물과 성장 진행도를 보여 주는 마을 화면 (예정)

## MVP 범위 (예정)

1. 자유 형식으로 일기를 남기고, 분석된 활동을 확인한다.
2. 기록에 따라 해당 건물의 경험치와 성장 상태를 갱신한다.
3. 마을 화면에서 변화와 건물 레벨을 확인한다.
4. 새로 접속해도 저장한 기록과 마을 상태를 불러온다.
5. 날짜별 지난 기록을 조회한다.

완료 기준은 활동 입력 → 저장 → 건물 성장 → 재접속 후 상태 복원까지 시연하는 것입니다. 첫 버전은 규칙 기반 성장을 계획합니다. 실제 AI 모델 연동, 친구 방문, 캐릭터, 자유 배치, 감정별 분위기 및 고급 애니메이션은 이후 검토할 확장 기능입니다.

## 백엔드 로컬 실행

Docker와 [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started)를 설치하고 저장소 루트에서 실행합니다.

```sh
supabase start
supabase db reset --local
supabase test db
```

`db reset --local`은 로컬 데이터를 초기화하고 마이그레이션을 다시 적용합니다. 테스트는 테스트용 계정을 만들어 권한, 일기 변경, 분석과 마을 성장 규칙을 검증한 뒤 롤백합니다.

`supabase status`에 표시되는 로컬 API URL과 공개용 키로 클라이언트를 만들고, 이메일과 비밀번호로 회원가입·로그인합니다. 이메일 확인이 필요한 경우 로컬 메일함을 사용합니다. 가입 시 프로필, 마을, 건물 및 구역 행이 생기며, 마이그레이션은 기존 Auth 사용자에게도 초기 행을 생성합니다.

### API 사용

로그인한 Supabase 클라이언트에서 호출합니다. 각 쓰기 결과의 `id`와 `revision`을 보관하고, 다음 쓰기에는 최신 `revision`을 전달합니다.

| 작업 | 호출 | 인자 |
| --- | --- | --- |
| 작성 | `rpc('create_diary', …)` | `p_entry_date` (YYYY-MM-DD), `p_content`, 선택 `p_title` |
| 조회 | `from('diary_entries').select('*, diary_activities(*)')` | 필요하면 `entry_date` 필터 및 정렬 |
| 수정 | `rpc('update_diary', …)` | `p_id`, `p_expected_revision`, `p_entry_date`, `p_content`, 선택 `p_title` |
| 삭제 | `rpc('delete_diary', …)` | `p_id`, `p_expected_revision` |
| 모의 분석 및 재분석 | `rpc('analyze_diary', …)` | `p_id`, `p_expected_revision` |
| 분석 결과 수정 | `rpc('set_diary_activities', …)` | `p_id`, `p_expected_revision`, `p_activities` (태그 배열) |
| 마을 조회 | `from('villages').select('*, village_areas(*, village_buildings(*))').single()` | 로그인한 계정의 마을 |

프로필의 닉네임과 마을 이름은 `profiles`에서 갱신합니다. 일기와 마을 데이터는 RLS로 본인에게만 공개하며, 일기·태그·성장 상태 변경은 소유자를 확인하는 RPC에서 처리합니다. 다른 계정의 일기 ID는 없는 일기와 동일하게 404를 반환합니다. 409가 발생하면 최신 일기를 읽은 뒤 변경 내용을 확인합니다.

### 초기 성장 규칙

| 조건 | 결과 |
| --- | --- |
| 시작 | 마을과 집 Lv.1, 시작 구역 해금 |
| 서로 다른 기록일 | 하루당 마을 XP 10, 누적 1·3·7일에 각각 마을 Lv.2·3·4 |
| 첫 일기 | 즉시 집 Lv.2 |
| 누적 기록 3일 / 7일 | 동쪽 / 남쪽 구역 해금 |
| 활동별 기록일 | 날짜당 건물 XP 10, 활동일 3일마다 해당 건물 레벨 1 증가 |

일기 날짜는 화면에서 선택한 달력 날짜를 전송합니다. 같은 날짜에 여러 일기를 작성할 수 있고, 마을 XP는 날짜당 한 번, 건물 XP는 활동별로 날짜당 한 번 계산합니다. 도서관·체육관·공원은 동쪽, 카페는 남쪽에 배치합니다. 화면에는 건물과 소속 구역이 모두 해금된 경우 표시합니다.

본문이나 제목이 바뀌면 기존 분석을 지우고 `pending`으로 되돌립니다. 날짜만 바꾸면 기존 태그를 새 날짜에 반영합니다. 사용자는 태그 목록을 직접 교체할 수 있고, 빈 목록도 확정할 수 있습니다. 재분석을 요청하면 수동 수정분을 포함한 기존 태그를 새 결과로 교체합니다. 현재 기록에 따라 성장 상태를 다시 계산하므로 삭제·수정·재분석으로 기준에 미달하면 레벨과 해금 상태도 내려갑니다. 같은 계정의 쓰기는 마을 행 잠금으로 직렬화되며, 일기 변경과 상태 재계산은 하나의 트랜잭션에서 처리됩니다.

### 분석 어댑터와 배포

현재 분석 어댑터 `haru_private.mock_analyze(text)`는 제목과 본문의 한국어·영어 키워드를 찾아 `study`, `exercise`, `rest`, `social`을 반환합니다. 분석은 별도 RPC로 호출하며 외부 서비스나 비밀 키가 필요 없습니다.

실제 모델을 연동할 때는 사용자 JWT를 검증하는 서버 또는 Supabase Edge Function에서 본인 일기를 읽고, 모델 결과를 허용된 태그로 검증한 뒤 해당 일기의 버전을 확인하며 저장합니다. 모델 출처를 구분하려면 DB에 서버 전용 저장 경로와 출처 값을 추가합니다. AI API 키와 Supabase 서비스 역할 키는 서버 환경 변수에 보관합니다. 브라우저에서는 프로젝트 URL, 공개용 키, 로그인 세션을 사용합니다.

호스팅 연결 정보가 준비되면 `supabase link --project-ref <project-ref>`, `supabase db push --dry-run`으로 대상과 적용 내용을 확인한 뒤 `supabase db push`로 적용합니다. 이 초기 구현은 호스팅된 Supabase에 배포되지 않았습니다.

## 학술제 소개

HARU LAND는 일상 기록과 게임의 성장 보상을 연결하는 개인 제작 프로젝트입니다. 학술제에서는 활동을 기록한 뒤 마을 건물이 생성·성장하고, 기록과 상태가 저장되는 흐름을 시연할 예정입니다. 기획 의도, 성장 규칙, 구현 과정 및 한계를 소개하는 자료와 시연 영상을 준비할 예정이며 제출 목표일은 12월 18일입니다.
